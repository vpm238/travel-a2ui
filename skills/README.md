# Generated skills

Everything in this directory is generated by the A2UI SDK's `SkillGenerator`,
driven by [`scripts/build_skills.py`](../scripts/build_skills.py), from the same
processor the server parses the model with:

```python
SkillGenerator(PROCESSOR.format)   # PROCESSOR is brain/catalog.py's
```

That format holds the travel catalog pruned to what this agent draws
(`catalogs/a2ui-travel/agent-components.json`), the macros, and the worked
examples (`catalogs/a2ui-travel/examples/*.json`). So a skill another agent
loads teaches exactly what this agent's model is taught and held to, and
`apps/server/tests/test_skills.py` fails if the two ever differ. Nothing is
edited after generation.

```bash
npm run generate      # rewrite them
npm run check         # fail if they are stale
```

| Skill | What it carries |
|---|---|
| `express-modular/a2ui-core` | The A2UI Express output contract: grammar, sentinel tags, data bindings, templates, surfaces. Identical for every catalog. |
| `express-modular/a2ui-travel` | The travel catalog as positional signatures, the macros, and the worked examples. |

**These are not the whole contract.** They say what components exist and how
to emit them. What the agent does *when* (which step comes next, how a route
is shaped, which control a decision is asked in, what data the host publishes
for a surface to bind) is authored markdown in [`prompts/`](../prompts),
because it is judgement rather than a catalog. Both halves reach the model in
the same system prompt.

The skills are instructions only: each directory holds a `SKILL.md` and
nothing else.
